Block 5: Integration and AI elements

Block 5 — integration inventory with gov-cloud column; AI assistive-only boundary for SF-86/FOCI PII.

Time: 60 minutes · Goal: Third-party inventory, identity, and the AI data path with a hard PII boundary

Work in: Integration and AI Elements

Focus from mind map

  • External parties: GCA, primes/subs, ISR, adjudication, CDSE, fingerprint providers, cloud/hosting
  • Integrations: DD 254 → access need; HR ↔ FSO adverse info; legal ↔ FOCI; ISSM ↔ FSO for system boundaries
  • AI: assistive only; does not replace sponsorship, adjudication, or FOCI determination; SF-86/FOCI PII sensitivity; official DCSA AI inventory = silence

Retrieval check

Question

Name three external systems and the mechanism each uses. Which control governs the AI data path?

Answer cues

Examples: NISS (web sponsorship/package/SF 328); eApp (DISS) (investigation initiation UI); STEPP/CDSE (LMS completions); eMASS (RMF package workflow); GCA via DD 254. AI control: default deny SF-86/FOCI PII into consumer AI; assistive use limited to non-PII checklists with human FSO/counsel approval; AI does not sponsor, adjudicate, or determine FOCI. Official DCSA AI tooling list remains silence.

Exit criteria

  • Third-party inventory complete with gov-cloud column; AI boundary stated affirmatively; context + AI path diagrams understood.
