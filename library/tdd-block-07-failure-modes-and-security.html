Block 7: Failure modes and security

Block 7 — failure modes across four views: package clocks, FOCI, cloud≠FCL, KMP, HR traps, AI oversharing.

Time: 45 minutes · Goal: What breaks, what leaks, and which control catches each tell

Focus from mind map

  • Incomplete first package / burn resubmits before Day 20
  • Undisclosed FOCI or late SF 328 material-change reporting
  • Confusing cloud IL / CMMC with FCL or classified ATO
  • Wrong KMP list
  • Adverse information trapped in HR
  • International partnerships under pre-2025 SF 328 mindset
  • Continuous vetting gaps after grant
  • AI oversharing of SF-86/FOCI PII

Sources

  • [S2][S3][S4][S9][S10][S12] · 04 - Integration and AI Elements failure table

Actions (tied to views)

  • Build a failure-mode table with columns: View · Failure · First tell · Control — covering conceptual, logical, physical, integration.
  • For each mind-map failure above, cite the view artifact that should have caught it (e.g., Day-20 clock → logical; 15% threshold → physical SF 328).
  • Add AI oversharing and third-party connector (fingerprint delay, HRIS stall) explicitly.
  • Affirm the post-2025 FOCI tell: teams still planning to the 30% threshold.

Retrieval check

Question

What is the most likely failure in a real FCL pursuit, and what is its first visible tell?

Answer cues

Highest-frequency teachable failure: incomplete Day-20 package / burned completeness cycles, tell = deficiency letters stacking while the clock runs. [S2][S10] Close rivals: wrong KMP list and FOCI under-disclosure (especially post-15% threshold). Cloud≠FCL is the most common architectural confusion in design reviews.

Exit criteria

  • Failure-mode table covers all four views; AI and HR traps included; 15% vs 30% called out.
